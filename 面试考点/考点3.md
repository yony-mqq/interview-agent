# AI Agent完整设计方法论（面试高频题）

> **面试官考察核心：** 你有没有从0到1设计Agent的完整方法论，而不是只会调API。

---

## 一、面试官视角的四条红线

### 1. 真正考察什么
- 有没有从0到1设计Agent的完整方法论，而不是只会调API。

### 2. 雷区：上来谈技术
- 一开口就聊模型选择 / API接口 / 框架选型，没有需求分析，**直接扣分**。

### 3. 雷区：缺少评测
- 只讲怎么搭，不讲怎么验证效果，说明没有真正上线过Agent。

### 4. 加分项：有案例
- 讲过程中自然带出真实项目案例，比如智能客服 / 导购 / 内容审核。

---

## 二、回答思路 — 四步设计流程

```
需求分析 → 任务拆解 → Prompt设计 → 评测上线
```

### Step 1: 需求分析
- **明确任务**：Agent要完成什么任务。
- **明确用户**：用户是谁，成功标准是什么。
- **界定边界**：AI做 vs 人做的边界在哪里。

### Step 2: 任务拆解
- **拆子任务链**：核心任务拆成子任务链。
- **选工具**：每个子任务匹配工具（API / 函数）。
- **定义协议**：定义输入输出协议。

### Step 3: Prompt设计
- **角色定义**：System Prompt定义角色和约束。
- **流程设计**：Workflow设计（串行 / 并行 / 分支）。
- **异常处理**：超时 / 失败 / 循环的处理机制。

### Step 4: 评测上线
- **构建评测集**：覆盖正常 + 边界场景。
- **过程指标**：准确率 / 步骤完成率。
- **结果指标**：任务完成率 / 满意度。

---

## 三、案例：智能客服Agent拆解

### 1. 子任务链
```
意图识别 → 知识检索 → 工单创建 → 转人工
```
每步独立可测试。

### 2. 工具选择
| 子任务 | 工具 |
|---|---|
| 意图识别 | NLU模型 |
| 知识检索 | RAG（向量检索 + 大模型生成） |
| 工单创建 | 业务API |

### 3. 异常处理
- **3轮未解决** → 自动转人工。
- **敏感词触发** → 合规拦截。
- **超时30s** → 降级为模板回复。

### 4. 评测设计
- **200条评测集**：常见问题100条 + 边界case 50条 + 对抗case 50条。
- **上线标准**：准确率 > 92% 才上线。

---

## 四、评测三层指标

### 1. 工具调用准确率
- 每个子任务是否调对了工具。
- 意图识别准确率 / 知识检索召回率。

### 2. 步骤完成率
- 整个任务链走到最后一步的比例。
- 中途断链说明设计有问题。

### 3. 端到端结果
- 用户问题解决率 / 满意度评分。
- 对比人工客服的解决率做 benchmark。

## 五、常见追问与回答策略

### Q1: Agent和RAG是什么关系？
**A:** RAG是Agent的一个工具，Agent调度RAG做知识检索。Agent是大脑，RAG是工具箱里的一把螺丝刀。

### Q2: 怎么处理幻觉？
**A:**
- 评测集里加对抗case。
- 设置置信度阈值，低于阈值不回答或转人工。
- Prompt中加防御性指令（"不确定就承认"）。

### Q3: 多Agent怎么协作？
**A:** Orchestrator模式 — 主Agent调度子Agent，每个子Agent独立Prompt + 独立评测。

---

## 六、核心总结

> **需求分析 → 任务拆解 → Prompt设计 → 评测上线，四步缺一不可。**

- 面试官最看重的**不是你用了什么框架**，而是你有没有从需求到上线的**完整闭环思维**。
- **评测不是加分项，是必选项** —— 没有评测的Agent等于没有质量保障的产品。
