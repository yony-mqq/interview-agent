## 一、数据勘误（重要）

| 原来文档中的说法 | 实际情况 | 建议写法 |
|---|---|---|
| 50+ 题目评测集 | 实际 **104 题** | 写"构建 100+ 题目自动化评测集" |
| 准确率 70% → 90% | 最新评测通过率 **70.2%**（10.73/15） | 若无基线对比，建议写"构建 100+ 题评测集，当前通过率 70%，持续优化中"；若有后续优化数据再更新 |
| Token 消耗降低 40% | 有滑动窗口+摘要机制，但无 A/B 对比数据 | 写"设计滑动窗口+对话摘要机制管理长上下文，有效控制 Token 消耗" |
| 首字延迟 < 800ms | 未实测确认 | 建议不写具体时间，或实测后再补充 |

> **原则**：简历上的每一个数字都要能解释来源。宁可不写具体数字，也不要写无法验证的数据。

## 四、面试对应话术（每个 bullet 展开 30 秒）

### Bullet 1: RAG 知识库检索

> "面试时 AI 容易幻觉，所以我做了完整的 RAG 流程。把个人经历写成 Markdown，按 `##` 标题切分，短段落合并成 500-800 字的 chunk，调用 text-embedding-v3 生成 1024 维向量。检索时用余弦相似度排序，阈值设了 0.65，取 Top3 注入 prompt。这样 LLM 回答时基于真实文档，不会编造我没做过的项目。"

**追问准备**：
- Q: 为什么选 500-800 字？A: 太短语义不完整，太长影响检索精度，500-800 是实验中平衡精度和召回的阈值
- Q: 阈值 0.65 怎么定的？A: 经验值，低于 0.65 的内容相关性下降明显，会引入噪声

### Bullet 2: MCP 协议

> "为了实现标准化工具调用，我手写了一个 MCP Server，没有引入官方 SDK。基于 Express 暴露两个接口：GET /tools 返回工具列表和 JSON Schema，POST /tools/call 执行具体逻辑。注册了 5 个工具，覆盖简历检索、技术栈、项目经验、性能数据、稳定性成果。还写了一个 stdio 桥接器，让 Cursor 和 Claude Code 也能调用。"

**追问准备**：
- Q: 为什么不用官方 SDK？A: 为了面试时能完整讲清楚底层通信机制，手写更可控，代码也更轻量
- Q: MCP 和 Function Calling 的区别？A: MCP 是协议标准，Function Calling 是具体实现；MCP 更通用，支持跨模型、跨工具

### Bullet 3: ReAct + SSE

> "后端 chat 接口按 ReAct 流程组织：先 Thought 分析意图，再 Action 调用检索工具，然后 Observation 拿到结果，最后 LLM 生成回答。每个步骤通过 SSE 事件发送到前端，前端用 ReadableStream 解析，实时显示思考过程。用户能看到 Agent 在'思考'、'检索'、'生成'，体验比直接等回答好很多。"

**追问准备**：
- Q: SSE 和 WebSocket 怎么选？A: 单向流式用 SSE 更简单，自动重连、兼容性好，不需要维护 WebSocket 连接
- Q: 粘包怎么处理的？A: SSE 按 `\n\n` 分隔事件，用 buffer 累积未完整的数据块，完整事件才解析 JSON

### Bullet 4: 对话记忆

> "长对话会超出 LLM 上下文窗口，我设计了分层记忆：近期对话用滑动窗口保留，从最新消息往前累加 token，超出 4000 预算就截断；更旧的消息累积到一定阈值后，调用轻量模型生成摘要。这样既能记住遥远的上下文，又不会 Token 爆炸。多会话通过 SQLite 持久化，刷新页面能恢复。"

**追问准备**：
- Q: 摘要和原始消息怎么平衡？A: 摘要占 500 token 预算，近期对话占剩余预算，system prompt 和当前输入各预留固定空间
- Q: 怎么保证摘要不丢失关键信息？A: 摘要是增量追加的，新摘要会合并到旧摘要前面，关键信息层层保留

### Bullet 5: 评测与部署

> "为了保证回答质量，我构建了 100+ 题目的评测集，覆盖项目经验、技术能力、行为面试等类别。用 LLM-as-a-Judge 机制，让更强的模型当裁判，从准确性、完整性、安全性三个维度打分。部署上前端放 OSS + CDN，后端放轻量服务器，还设计了不可变部署方案——每次发布创建独立版本目录，回滚时改符号链接，1 秒内完成。"

**追问准备**：
- Q: 评测集怎么构建的？A: 基于真实面试高频题，涵盖常见 case、边界 case、对抗 case（如 prompt 注入）
- Q: 回滚方案具体怎么做的？A: releases/ 目录存所有历史版本，current 是符号链接指向当前版本，PM2 cwd 读 current，回滚 = 改链接 + reload

## 五、可能被追问的点（提前准备）

| 问题 | 简要回答 |
|---|---|
| 这个项目花了多久？ | 核心功能 2-3 周，持续优化中。每天 3-4 小时。40% 时间在后端 RAG/Prompt，30% 在前端流式交互，20% 在 MCP，10% 在评测。 |
| 如果重来会改进什么？ | ① 多 Agent 架构（Router + Specialist）② 意图识别从正则升级到轻量分类模型 ③ 加 ASR/TTS 实现真正的实时语音面试模拟 |
| 最大难点是什么？ | Prompt 调优——怎么让 LLM 既基于知识库又不死板、既结构化又不啰嗦。通过评测集量化反馈，迭代了多轮。 |
| 这个项目有什么价值？ | 自用为主，但模式可复用：换一个人的知识库就是另一个人的面试助手；换成产品文档就是智能客服；换成代码规范就是 Code Review 助手。 |
