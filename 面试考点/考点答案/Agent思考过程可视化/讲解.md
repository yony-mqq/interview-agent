# Agent 思考过程可视化

> **核心定位**：让面试官（用户）看到 Agent "脑子在想什么"，而不只是看到最终答案。

---

## 一、没有可视化的现状

现在聊天界面是这样的：

```
面试官：介绍一下你的项目经验
─────────────────────────────
[空 → 光标闪烁 → 直接出现完整回答]
```

用户完全不知道 Agent 在背后做了什么。它检索了知识库吗？调用了什么工具？分析出了什么意图？一概不知。

这带来两个问题：
1. **面试讲不清楚** — 面试官问"你的 Agent 是怎么工作的"，你说"它先检索再生成"，但代码里完全没有体现这个"先"和"再"
2. **用户体验差** — 大模型生成慢的时候，用户干等几秒不知道在干嘛，会觉得"卡了"

---

## 二、具象化的表现

改造后，聊天界面会变成这样：

```
面试官：介绍一下你的项目经验
─────────────────────────────
🤔 正在分析用户意图...         ← 思考过程，可展开/折叠
   └─ 识别到：技术经验类问题
   └─ 匹配岗位：前端开发

🔍 正在检索知识库...           ← 工具调用过程
   └─ 查询："项目经验 前端"
   └─ 命中 3 条文档

✍️ 正在生成回答...             ← 生成阶段
   └─ 已检索到相关内容，组织回答中...

我在 XX 公司负责了 XX 项目，技术栈是 React + TypeScript...
这是我的回答内容，从这里开始...
```

### 每个阶段对应后端在做什么

| 前端看到 | 后端实际在做 | 事件类型 |
|---|---|---|
| 🤔 正在分析用户意图... | System Prompt 引导 LLM 先输出思考 | `type: "thought"` |
| 🔍 正在检索知识库... | 调用 `retrieveRelevantChunks()` | `type: "tool_call"` |
| 📄 找到 3 条文档... | 检索完成，返回结果 | `type: "tool_result"` |
| ✍️ 正在生成回答... | 组装 Prompt，调用 LLM 生成 | `type: "content"` |

---

## 三、技术实现的核心变化

### 1. 后端：SSE 流里不再只发 content

**现在的 SSE 格式：**

```http
data: {"content":"我"}\n\n
data: {"content":"在"}\n\n
data: {"content":"XX"}\n\n
data: [DONE]\n\n
```

**改造后的 SSE 格式：**

```http
data: {"type":"thought","content":"用户问的是技术经验类问题，需要检索项目文档"}\n\n
data: {"type":"tool_call","name":"retrieveRelevantChunks","input":"项目经验 前端"}\n\n
data: {"type":"tool_result","name":"retrieveRelevantChunks","output":"命中3条：接送列表、性能优化、AI工程化"}\n\n
data: {"type":"content","content":"我在XX公司..."}\n\n
data: {"type":"content","content":"负责了..."}\n\n
data: [DONE]\n\n
```

前端根据 `type` 字段决定渲染方式：
- `type: "thought"` → 灰色小字，放在折叠面板里
- `type: "tool_call"` → 带图标的工具调用卡片
- `type: "tool_result"` → 显示检索结果条数
- `type: "content"` → 正常的大号回答文字

### 2. 前端：MessageBubble 不再是纯文本

**现在的 MessageBubble：**

```tsx
<div className="bg-gray-100 rounded-xl">
  <span dangerouslySetInnerHTML={renderMarkdown(content)} />
  {isStreaming && <span className="animate-pulse">|</span>}
</div>
```

**改造后的 MessageBubble：**

```tsx
<div className="bg-gray-100 rounded-xl">
  {/* 思考过程折叠面板（只有 assistant 消息有） */}
  {thinkingSteps.length > 0 && (
    <div className="border-b border-gray-200 mb-2">
      <button onClick={() => setExpanded(!expanded)}>
        🤔 思考过程 ({thinkingSteps.length} 步)
      </button>
      {expanded && thinkingSteps.map(step => (
        <div key={step.id}>{step.icon} {step.content}</div>
      ))}
    </div>
  )}

  {/* 最终回答内容 */}
  <span dangerouslySetInnerHTML={renderMarkdown(content)} />

  {isStreaming && <span className="animate-pulse">|</span>}
</div>
```

### 3. 真正的 ReAct 循环

现在的 chat.ts 流程是：

```
用户输入 → 检索 → 组装 Prompt → 调用 LLM → 流式输出
```

改造后要变成真正的 ReAct：

```
用户输入
  │
  ▼
[Thought] LLM 先思考："这个问题需要检索知识库"
  │
  ▼
[Action] 调用 retrieveRelevantChunks("项目经验")
  │
  ▼
[Observation] 检索结果："命中3条文档..."
  │
  ▼
[Thought] LLM 再思考："结合检索结果，我应该这样回答..."
  │
  ▼
[Action] 调用 LLM 生成最终回答
  │
  ▼
[Observation] 流式输出最终内容
```

每次 Thought/Action/Observation 都通过 SSE 推给前端，用户实时看到 Agent 的"脑子在转"。

## 四、改造后的完整交互体验

假设面试官输入"说说你做过的最有挑战的事"：

**第 1 秒（思考阶段）：**

```
🤔 正在分析意图...
   └─ 识别为：行为面试题（STAR 模型）
```

**第 2 秒（工具调用阶段）：**

```
🔍 正在检索知识库...
   └─ 查询关键词："挑战 困难 解决"
   └─ 命中 2 条：稳定性建设、性能优化
```

**第 3 秒（生成阶段）：**

```
✍️ 正在组织回答...
```

**第 4~8 秒（内容流式输出）：**

```
我在做 XX 项目时遇到的最大挑战是...
[逐字出现]
```

**全部完成后，思考面板自动折叠，只保留最终回答。**

## 五、为什么这个改造面试价值最高

对照考点：

| 考点 | 改造后你能讲什么 |
|---|---|
| **1.1 ReAct 循环** | "我实现了 Thought→Action→Observation 的完整循环，不是简单 Chain" |
| **2.1 工具调用** | "Agent 会自主判断何时调用知识库检索，调用过程实时展示" |
| **3.2 思考过程展示** | "前端用折叠面板展示思考链，用户体验和可解释性兼备" |
| **考点3 评测** | "每个步骤独立可观测，方便做步骤完成率的评测" |

一句话：**面试官打开你的聊天界面，不用你解释，他自己就看到了"这是 Agent，不是 ChatBot"。**

---

## 六、核心改造点总结

改造的核心就是三步：

1. **后端 SSE 流里加 `type` 字段区分事件类型**
2. **chat.ts 里把"检索→生成"拆成 ReAct 的多个步骤，每步发一个事件**
3. **前端 MessageBubble 支持折叠面板，按 `type` 渲染不同样式**
