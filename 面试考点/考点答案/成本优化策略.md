# 成本优化策略

> **面试高频题**："这个项目怎么控制成本？Token 消耗怎么优化的？"

---

## 一、项目当前成本现状

你的项目里，LLM 调用集中在两处：

| 调用点 | 模型 | 频率 | 成本 |
|---|---|---|---|
| 主聊天接口 `chat.ts` | qwen-plus | 每轮对话 | 高 |
| 摘要生成 `summaryService.ts` | qwen-turbo | 溢出时触发 | 低（已优化） |
| Embedding `embedder.ts` | text-embedding-v3 | 每轮检索 | 免费 |

**核心问题：所有主对话都走 qwen-plus，没有分层路由，没有缓存。**

---

## 二、成本优化三层策略

### 第一层：模型分层路由（省大头）

**核心思想：简单任务用便宜模型，复杂任务才用贵模型。**

DashScope 模型成本对比（约）：

| 模型 | 输入价格（元/M tokens） | 适用场景 |
|---|---|---|
| qwen-turbo | 0.5 | 摘要生成、意图识别、简单问答 |
| qwen-plus | 2.0 | 复杂推理、面试回答生成 |

**qwen-turbo 的成本只有 qwen-plus 的 1/4。**

#### 具体方案

```typescript
// modelRouter.ts
export async function routeChat(
  messages: Message[],
  complexity: 'low' | 'medium' | 'high'
): AsyncGenerator<string> {
  const model = complexity === 'high' ? 'qwen-plus' : 'qwen-turbo';

  const stream = await client.chat.completions.create({
    model,
    messages,
    stream: true,
  });

  for await (const chunk of stream) {
    yield chunk.choices[0]?.delta?.content || '';
  }
}
```

**复杂度判断规则：**

| 复杂度 | 判断条件 | 路由模型 |
|---|---|---|
| low |  greetings（"你好"）、简单确认（"知道了"）| qwen-turbo |
| medium | 单轮技术问答、FAQ 类问题 | qwen-turbo |
| high | 追问细节、需要多步推理、STAR 模型回答 | qwen-plus |

**你的项目里已经做了一件事（很好）：**

`summaryService.ts` 里生成摘要已经用了 `qwen-turbo`：

```typescript
const response = await client.chat.completions.create({
  model: 'qwen-turbo', // 轻量模型，成本低
  // ...
});
```

### 第二层：结果缓存（省重复）

**核心思想：相同的问题，直接返回缓存结果，不走 LLM。**

#### 方案 1: 精确匹配缓存

```sql
CREATE TABLE IF NOT EXISTS response_cache (
  query_hash TEXT PRIMARY KEY,  -- query 的 MD5
  query TEXT NOT NULL,
  response TEXT NOT NULL,
  model TEXT NOT NULL,
  hit_count INTEGER DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

```typescript
// cacheService.ts
export function getCachedResponse(query: string): string | null {
  const hash = md5(query.trim().toLowerCase());
  const stmt = db.prepare('SELECT response FROM response_cache WHERE query_hash = ?');
  const row = stmt.get(hash) as { response: string } | undefined;

  if (row) {
    db.prepare('UPDATE response_cache SET hit_count = hit_count + 1 WHERE query_hash = ?').run(hash);
    return row.response;
  }
  return null;
}

export function setCachedResponse(query: string, response: string, model: string): void {
  const hash = md5(query.trim().toLowerCase());
  const stmt = db.prepare(`
    INSERT INTO response_cache (query_hash, query, response, model)
    VALUES (?, ?, ?, ?)
    ON CONFLICT(query_hash) DO UPDATE SET
      response = excluded.response,
      hit_count = hit_count + 1,
      created_at = CURRENT_TIMESTAMP
  `);
  stmt.run(hash, query, response, model);
}
```

**适合缓存的问题：**
- "介绍一下你的项目经验"
- "你的技术栈是什么"
- "做过最有挑战的事"

这些高频问题，第一次生成后缓存，后续直接命中。

#### 方案 2: RAG 检索结果缓存

```typescript
// embeddingCache.ts
const embeddingCache = new Map<string, number[]>();

export async function getCachedEmbedding(text: string): Promise<number[]> {
  const key = md5(text);
  if (embeddingCache.has(key)) {
    return embeddingCache.get(key)!;
  }
  const embedding = await getEmbedding(text);
  embeddingCache.set(key, embedding);
  return embedding;
}
```

相同 query 的 Embedding 不用重复请求 API。

### 第三层：Token 预算控制（省浪费）

**核心思想：严格控制输入输出的 Token 数，不浪费一分钱。**

你的项目里已经做了一件事（很好）：

`memoryManager.ts` 里的滑动窗口 + 摘要机制，本质上就是 Token 预算控制：

```typescript
const TOTAL_CONTEXT_BUDGET = 4000;
const SYSTEM_PROMPT_RESERVE = 1200;
const CURRENT_INPUT_RESERVE = 500;
const SLIDING_WINDOW_BUDGET = TOTAL_CONTEXT_BUDGET - SYSTEM_PROMPT_RESERVE - CURRENT_INPUT_RESERVE;
```

**还可以加的两件事：**

#### 1. 输出长度限制

```typescript
const stream = await client.chat.completions.create({
  model: 'qwen-plus',
  messages,
  stream: true,
  max_tokens: 800,  // ← 限制回答长度，防止长文输出烧 Token
});
```

面试回答本来就应该简洁，800 token（约 400 中文字）足够。

#### 2. 输入截断保护

```typescript
// 如果用户输入超长，直接截断
const MAX_INPUT_LENGTH = 500;
const safeInput = userInput.slice(0, MAX_INPUT_LENGTH);
```

防止用户粘贴大段文本刷 Token。

## 三、成本监控（知道省了多少）

```typescript
// costTracker.ts
interface CostRecord {
  timestamp: string;
  model: string;
  inputTokens: number;
  outputTokens: number;
  cost: number;  // 元
}

// DashScope 价格表（元 / 1K tokens）
const PRICE_TABLE = {
  'qwen-plus': { input: 0.002, output: 0.006 },
  'qwen-turbo': { input: 0.0005, output: 0.0015 },
};

export function trackCost(model: string, inputTokens: number, outputTokens: number): void {
  const price = PRICE_TABLE[model] || PRICE_TABLE['qwen-plus'];
  const cost = (inputTokens * price.input + outputTokens * price.output) / 1000;

  console.log(`[Cost] ${model}: ${inputTokens} in + ${outputTokens} out = ¥${cost.toFixed(4)}`);

  // 可持久化到数据库做报表
}
```

## 四、面试话术

> **"你怎么控制项目成本？"**
>
> 我们做了三层优化。第一层是模型分层路由，简单问答走 qwen-turbo（成本只有 qwen-plus 的 1/4），只有复杂推理才走 qwen-plus。摘要生成已经用了 qwen-turbo。
>
> 第二层是结果缓存，高频问题比如"介绍项目经验"第一次生成后缓存到 SQLite，后续相同问题直接命中，不走 LLM。Embedding 结果也用内存缓存，避免重复请求。
>
> 第三层是 Token 预算控制，通过滑动窗口管理上下文长度，限制 max_tokens=800，防止超长输出烧 Token。输入也做了截断保护，防止用户粘贴大段文本。
>
> 我们还做了成本监控，每次调用记录 input/output token 和费用，方便评估优化效果。三层叠加下来，预计可以把 Token 消耗降低 50% 以上。

## 五、一句话总结

| 策略 | 手段 | 预期节省 |
|---|---|---|
| **模型分层** | 简单任务走 qwen-turbo | 30-40% |
| **结果缓存** | 高频问题直接命中 | 20-30% |
| **Token 预算** | 滑动窗口 + max_tokens 限制 | 10-20% |
| **成本监控** | 记录每次调用费用 | —（可观测） |
