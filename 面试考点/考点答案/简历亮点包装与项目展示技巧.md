# 简历亮点包装与项目展示技巧

> **面试高频题**："介绍一下你做过的最有成就感的项目"、"这个 Agent 项目有什么亮点？"
> **考点1 强调**："强调自己实现的核心逻辑，展示完整的业务闭环。"
> **考点2 强调**："简历亮点包装，核心架构、全栈开发、性能优化、效果评估。"

---

## 一、项目名称包装

**不要**：AI 面试助手
**要**：AI 智能面试教练（Personal Interview Agent）

**命名原则**：
- 加"智能"、"AI"体现技术深度
- 加"教练"体现产品思维（不是工具，是助手）
- 英文名称体现国际化视野

---

## 二、项目描述四段式

### 1. 一句话定位

> "基于 LangGraph 构建多步推理工作流，实现了意图识别、知识库检索（RAG）、答案生成的自动化编排。"

**要点**：
- 提到核心技术（LangGraph、RAG）
- 提到完整流程（意图识别 → 检索 → 生成）
- 体现"自动化编排"（不是手动调 API）

---

### 2. 技术架构（30 秒版本）

```
前端：React + TypeScript + SSE 流式渲染
后端：Node.js + Express + OpenAI 兼容接口
数据：Markdown 知识库 + 向量索引（text-embedding-v3）
协议：MCP（Model Context Protocol）标准化工具调用
```

**面试时展开说**：
> "前端用 React + TypeScript，实现了 SSE 流式输出的打字机效果和 Markdown 实时解析。后端用 Node.js + Express，对接通义千问的 OpenAI 兼容接口。数据层把个人经历写成 Markdown 知识库，用 text-embedding-v3 生成向量索引。还实现了一个轻量级 MCP Server，标准化工具调用。"

---

### 3. 核心亮点（必背，面试重点问）

#### 亮点一：RAG 检索增强

> "为了回答基于真实经历的问题，我实现了完整的 RAG 流程：按 `##` 标题切分 Markdown，短段落合并成 500-800 字 chunk，调用 text-embedding-v3 生成向量，在线检索时用余弦相似度排序取 Top3。还做了增量更新——用 MD5 判断文件变更，只重新生成变更文件的 embedding。"

**数据支撑**：
- 知识库：XX 个 Markdown 文件
- 切分策略：`##` 标题切分 + 短段落合并
- 检索精度：Top3 召回率 > 80%

---

#### 亮点二：MCP 协议实现

> "为了实现标准化工具调用，我手写了一个 MCP Server，暴露 5 个工具：search_resume、get_tech_stack、get_project_experience 等。GET /mcp/tools 返回工具定义，POST /mcp/tools/call 执行具体逻辑。还实现了 stdio 桥接器，兼容 Cursor、Claude Code 等外部工具。"

**数据支撑**：
- 工具数量：5 个
- 协议兼容：HTTP + stdio 桥接
- 外部工具兼容：Cursor、Claude Code

---

#### 亮点三：性能优化

> "通过滑动窗口算法管理上下文，结合向量检索，将 Token 消耗降低 40%。首字延迟控制在 800ms 以内，全程使用 SSE 流式传输，用户感知延迟很低。"

**数据支撑**：
- Token 消耗降低：40%
- 首字延迟（TTFT）：< 800ms
- 流式协议：SSE

---

#### 亮点四：评测体系

> "构建了包含 50+ 题目的自动化评测集（Eval Set），覆盖常见 case、边界 case、对抗 case。利用 LLM-as-a-Judge 机制持续优化 Prompt，回答准确率从初始的 70% 提升到 90%。"

**数据支撑**：
- 评测集规模：50+ 题目
- 覆盖类型：常见 + 边界 + 对抗
- 准确率提升：70% → 90%

## 三、面试展示技巧

### 1. 讲架构时画流程图

```
用户提问
    │
    ▼
┌─────────────┐
│  意图识别    │  ← 正则规则匹配
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  RAG 检索   │  ← 向量相似度，Top3
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  MCP 调用   │  ← 结构化查询
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  LLM 生成   │  ← qwen-plus 流式
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  SSE 输出   │  ← 打字机效果
└─────────────┘
```

**面试话术**：
> "我画一下架构图。用户提问后，第一步意图识别（正则匹配），第二步 RAG 检索（向量相似度取 Top3），第三步 MCP 调用（结构化查询），第四步 LLM 生成（qwen-plus 流式），第五步 SSE 输出到前端。整个流程 3 步走数据、1 步走生成。"

---

### 2. 讲问题时带解决方案

**不要只讲成果，要讲"遇到了什么问题、怎么解决的"**。

| 问题 | 解决方案 | 效果 |
|---|---|---|
| RAG 检索不到相关内容 | 加相似度阈值过滤 + 优雅降级 | 避免塞无关内容 |
| LLM 生成速度慢 | SSE 流式 + 前端打字机效果 | 用户感知延迟降低 |
| MCP 不兼容外部工具 | 实现 stdio 桥接器 | 支持 Cursor、Claude Code |
| 上下文太长 Token 贵 | 滑动窗口 + 对话摘要 | Token 消耗降低 40% |
| 评测成本高 | LLM-as-a-Judge 自动化打分 | 节省人工评测时间 |

## 四、常见追问与回答

### Q: 这个项目花了多长时间？

**回答**：
> "核心功能开发了大约 2 周，后续持续优化了 1 周。每天投入 3-4 小时。时间分配：40% 在 RAG 和 Prompt 调优，30% 在 MCP 实现，20% 在前端流式输出，10% 在评测体系。"

### Q: 如果让你重新做，你会改进什么？

**回答**：
> "三个改进方向：
> 1. **多 Agent 架构** — 目前单 Agent 够用，但复杂场景下可以拆成 Router + Specialist 模式
> 2. **更智能的意图识别** — 目前用正则，未来可以用轻量级模型做语义分类
> 3. **实时语音交互** — 加上 ASR（语音识别）和 TTS（语音合成），实现真正的实时面试模拟"

### Q: 这个项目有什么实际使用场景？

**回答**：
> "目前主要是自用——模拟面试、准备面试回答。但扩展性很好：
> - 换一个人的知识库，就是另一个人的面试助手
> - 把知识库换成产品文档，就是智能客服
> - 把知识库换成代码规范，就是 Code Review 助手
>
> 核心是'知识库 + RAG + Agent'这个模式，可以复用到很多场景。"
