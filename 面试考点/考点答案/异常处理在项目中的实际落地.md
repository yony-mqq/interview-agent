# 异常处理在项目中的实际落地

> **面试高频题**："你项目中的异常处理是怎么做的？能具体讲讲吗？"
> **说明**：本文档是对 interview-agent 项目中异常处理代码的逐层梳理，面试时可按此结构回答。

## 一、总体设计：四层防护体系


## 二、第一层：全局兜底 errorHandler.ts

**文件**：`server/src/middleware/errorHandler.ts`

### 2.1 AppError 业务错误类

```typescript
export class AppError extends Error {
  constructor(
    public statusCode: number,
    message: string,
    public code?: string
  ) {
    super(message);
    this.name = 'AppError';
  }
}
```

**作用**：区分已知业务错误（参数非法、权限不足）和未知系统错误（数据库挂了、LLM 超时）。

### 2.2 asyncHandler 包装器

```typescript
export function asyncHandler(fn) {
  return (req, res, next) => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
}
```

**作用**：自动捕获 async 路由中的异常并交给 Express 的错误中间件，避免 async 错误导致进程崩溃。

### 2.3 SSE 场景特殊处理

```typescript
if (err instanceof AppError) {
  if (!res.headersSent) {
    res.status(err.statusCode).json({ error: err.message });
  } else {
    // SSE 已建立，发 error 事件后关闭
    res.write(`data: ${JSON.stringify({ type: 'error', error: err.message }) }\n\n`);
    res.end();
  }
}
```

**关键点**：SSE 连接一旦建立，不能再返回 JSON，必须以 SSE error 事件告知前端，避免客户端挂死。

## 三、第二层：主接口降级 chat.ts

**文件**：`server/src/routes/chat.ts`

主接口 `POST /api/chat` 嵌套了 **5 层 try-catch + 1 层参数校验**：

### 3.1 参数校验（Fast Fail）

```typescript
if (!message || typeof message !== 'string') {
  res.status(400).json({ error: 'message is required' });
  return;
}

// 输入截断保护：防止超长输入刷 Token
const MAX_INPUT_LENGTH = 500;
const safeMessage = message.slice(0, MAX_INPUT_LENGTH);
```

### 3.2 权限检查

```typescript
if (!conversationBelongsToUser(conversation_id, user_id)) {
  res.status(404).json({ error: 'Conversation not found' });
  return;
}
```

### 3.3 RAG 检索降级

```typescript
let contextText = '';
try {
  const chunks = await retrieveRelevantChunks(safeMessage, 3);
  if (chunks.length > 0) {
    contextText = chunks.map(...).join('\n\n');
  }
} catch (error) {
  console.warn('[Chat] Retrieval failed, proceeding without context:', error);
}
```

**降级行为**：检索失败 → `contextText` 为空 → LLM 基于通用知识回答。

### 3.4 MCP 调用降级

```typescript
let mcpContext = '';
try {
  mcpContext = await runMCPForQuery(safeMessage);
} catch (error) {
  console.warn('[Chat] MCP call failed, proceeding without MCP context:', error);
}
```

**降级行为**：MCP 失败 → `mcpContext` 为空 → 跳过结构化查询。

### 3.5 Memory 构建降级

```typescript
let memoryContext;
try {
  memoryContext = await buildMemoryContext(conversationId, safeMessage);
} catch (error) {
  console.warn('[Chat] Memory build failed, fallback to raw history:', error);
  memoryContext = { summary: '', recentMessages: history, overflowCount: 0, totalTokens: 0 };
}
```

**降级行为**：Memory 失败 → 回退到原始 `history`，summary 为空。

### 3.6 LLM 流式生成降级

```typescript
try {
  for await (const content of streamChat(messages, selectedModel)) {
    if (isClientDisconnected) break;
    assistantContent += content;
    sendEvent(res, { type: 'content', content });
  }
} catch (error) {
  if (!isClientDisconnected) {
    console.error('[Chat] Stream error:', error);
    sendEvent(res, { type: 'error', error: 'Generation failed' });
  }
}
```

**降级行为**：流式生成失败 → 发送 SSE error 事件，前端显示"生成失败"。

### 3.7 客户端断开检测

```typescript
let isClientDisconnected = false;
req.on('close', () => { isClientDisconnected = true; });

// 每次写数据前检查
if (isClientDisconnected) break;
```

**作用**：避免客户端断开后服务端继续写数据，浪费资源。

### 3.8 最外层兜底

```typescript
try {
  // ... 上面所有逻辑
} catch (error) {
  console.error('[Chat] Unexpected error:', error);
  if (!res.headersSent) {
    res.status(500).json({ error: 'Internal server error' });
  } else {
    res.end();
  }
}
```

## 四、第三层：各服务独立防护

### 4.1 retriever.ts（RAG 检索）

```typescript
function loadVectorStore(): VectorStore {
  try {
    const data = readFileSync(vectorsPath, 'utf-8');
    vectorStore = JSON.parse(data);
    return vectorStore;
  } catch (error) {
    console.warn('[Retriever] Failed to load vectors:', error);
    vectorStore = { chunks: [] };
    return vectorStore;
  }
}
```

- `vectors.json` 加载失败 → 返回 `{chunks: []}`
- 向量维度不匹配 → `cosineSimilarity` 返回 0
- 除零保护 → `denominator === 0` 时返回 0

### 4.2 mcp/client.ts（工具调用）

```typescript
export async function listMCPTools(): Promise<ToolInfo[]> {
  try {
    const response = await fetch(`${MCP_BASE_URL}/mcp/tools`);
    return data.tools || [];
  } catch (error) {
    console.warn('[MCP Client] Failed to list tools:', error);
    return [];
  }
}

export async function callMCPTool(name, args): Promise<MCPToolResult> {
  try {
    const response = await fetch(...);
    return await response.json();
  } catch (error) {
    return { content: [{ type: 'text', text: `调用工具失败` }], isError: true };
  }
}
```

- 工具列表获取失败 → 返回 `[]`
- 单个工具调用失败 → 返回 `{isError: true}`
- `runMCPForQuery` 检测到 `isError` → 返回空字符串

### 4.3 llm.ts（模型调用）

```typescript
const client = new OpenAI({
  apiKey: process.env.DASHSCOPE_API_KEY || '',
  baseURL: '...',
  timeout: 30000,  // 30秒超时
});
```

- OpenAI SDK 自带 30 秒超时
- 流式调用失败 → 抛出 `"LLM service unavailable"`

### 4.4 embedder.ts（Embedding）

```typescript
export async function getEmbedding(text: string): Promise<number[]> {
  try {
    const response = await client.embeddings.create({ model: 'text-embedding-v3', input: text });
    return response.data[0].embedding;
  } catch (error) {
    console.error('[Embedder] Failed:', error);
    throw new Error('Embedding service unavailable');
  }
}
```

- API 失败 → 抛出异常（外层 catch）
- 内存缓存上限控制 → 超过 500 条清空旧缓存

### 4.5 memoryManager.ts（记忆管理）

```typescript
try {
  const newSummary = await generateSummary(overflowMessages);
  // ...
} catch (error) {
  console.warn('[Memory] Summary generation failed, using existing summary:', error);
}
```

- 摘要生成失败 → 继续使用旧摘要
- 摘要压缩失败 → 截取前 300 字兜底

### 4.6 cacheService.ts（缓存）

```typescript
export function isCacheable(query: string): boolean {
  if (q.length > 100) return false;
  if (/为什么|怎么|如何|详细|具体/.test(q)) return false;
  return true;
}
```

- 追问类问题不缓存，避免缓存污染
- 缓存过期自动清理（7天 TTL）

### 4.7 accessControlService.ts（访问控制）

- 频率限制：同一邮箱 1 小时最多 5 次申请
- 验证码尝试次数限制：最多 3 次
- 过期记录自动清理

## 五、第四层：前端容错 useChat.ts

**文件**：`client/src/hooks/useChat.ts`

| 场景 | 处理方式 |
|---|---|
| HTTP 非 200 | `throw new Error('HTTP ${status}')` |
| 无 ReadableStream | `throw new Error('No reader available')` |
| SSE 解析错误 | `try-catch` 包裹 `JSON.parse`，出错 skip |
| 后端返回 `error` 字段 | `throw new Error(parsed.error)` |
| 用户主动取消（Abort） | `error.name === 'AbortError'` 静默处理 |
| 其他错误 | 兜底文案：`"抱歉，请求出错了，请稍后重试。"` |

| 考点答案写的 | 项目中实际落地 | 覆盖度 |

## 七、面试话术（完整版）

> **"你项目中的异常处理是怎么做的？"**
>
> 我分了四层防护。
>
> **第一层是全局兜底**：Express 全局 errorHandler 中间件，区分 AppError 业务错误和未知系统错误。SSE 场景有特殊处理——如果响应头已发送，不能再返回 JSON，必须以 SSE error 事件告知前端，避免客户端挂死。还有一个 asyncHandler 包装器，自动捕获 async 路由中的异常。
>
> **第二层是主接口降级**：`POST /api/chat` 里，RAG 检索、MCP 调用、Memory 构建、LLM 流式生成每个外部依赖都有独立的 try-catch。RAG 失败就空上下文走，MCP 失败就跳过结构化查询，Memory 失败就回退到原始 history，LLM 失败就发 SSE error 事件。每个失败都不打断主流程。另外做了客户端断开检测，避免断连后继续写数据。
>
> **第三层是各服务独立防护**：retriever 加载向量失败返回空数组；MCP client 工具调用失败返回 `isError: true`；Embedding 有内存缓存上限控制；Memory 摘要生成失败用旧摘要兜底；缓存服务有追问不缓存和 TTL 过期策略；访问控制有频率限制和验证码尝试次数限制。
>
> **第四层是前端容错**：HTTP 错误、SSE 解析错误、用户主动取消都有处理，其他错误会给兜底文案"抱歉，请求出错了，请稍后重试"。
>
> **目前还没做的**：异常重试和指数退避（因为 qwen-plus 稳定性还可以），以及用户反馈闭环（点赞/点踩）。如果后续接入多模型供应商，会加上自动重试和模型切换降级。
