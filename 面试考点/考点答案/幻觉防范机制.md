# 幻觉防范机制

> **面试高频题**："如果面试官问了一个你完全不知道的技术，你的 Agent 会胡编乱造吗？你是怎么防止幻觉的？"
> **考点1**："增加约束和反馈机制，Prompt 中加入'不知道就承认'的约束。"
> **考点2**："System Prompt 里加严格的防御性指令，如果检索不到相关信息直接告诉用户不确定。"

---

## 一、什么是幻觉（Hallucination）

幻觉 = LLM 生成**听起来合理但实际不存在**的信息。

**面试场景的典型幻觉**：

| 场景 | 幻觉示例 | 真实情况 |
|---|---|---|
| 项目数据 | "秒开率优化到了 95%" | 实际是 80% |
| 技术细节 | "用了 Next.js 的 ISR" | 实际没用 ISR |
| 时间线 | "2022 年负责的接送列表" | 实际是 2021 年 |
| 不存在的信息 | "还做过一个电商小程序" | 根本没做过 |

**为什么面试最怕幻觉：**
- 面试官比你懂技术，编造的数据一眼识破
- 一次幻觉 = 诚信问题，直接挂

## 二、五层幻觉防护体系

```
┌─────────────────────────────────────────────────────────────┐
│                    幻觉防护体系                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   第一层：知识边界锁定（RAG + MCP）                           │
│   └── 只让 LLM 基于检索到的真实文档回答                        │
│                                                             │
│   第二层：Prompt 防御性指令                                    │
│   └── "不知道就承认"、"不要编造"、"基于上下文回答"             │
│                                                             │
│   第三层：检索阈值过滤                                        │
│   └── 相似度 < 0.65 的结果丢弃，不塞进 Prompt                 │
│                                                             │
│   第四层：输出后校验                                          │
│   └── 检查回答中是否有文档里没有的数据                          │
│                                                             │
│   第五层：用户反馈闭环                                        │
│   └── 点赞/点踩收集，持续优化                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、每层详细实现

### 第一层：知识边界锁定

**核心思想**：LLM 能看到的"素材"只有知识库检索结果，没有其他来源。

```typescript
// 组装 Prompt 时，只放入检索到的 chunks
const contextText = chunks
  .map((chunk, i) => `[${i + 1}] ${chunk.title}\\n${chunk.content}`)
  .join('\\n\\n');

const systemContent = `
你是马倩倩的面试回答助手...

以下是相关项目文档供参考：
${contextText}  // ← LLM 只能基于这些回答

【重要约束】
- 只能基于上面提供的文档回答
- 如果文档中没有相关信息，坦诚告知"这个我不确定"
- 不要编造文档中没有的数据
`;
```

**为什么有效？**
- LLM 不是"知道答案"，而是"基于素材组织语言"
- 把素材范围锁死，LLM 就没法编造

---

### 第二层：Prompt 防御性指令

System Prompt 里明确写清楚"什么不能做"。

```markdown
【防御性指令】
1. 若上下文中没有相关信息，坦诚告知"这个我不太确定"或"文档中没有提到"
2. 不要编造不存在的数据、时间、技术细节
3. 不要夸大成果，文档里写 80% 就不要说 95%
4. 不要回答与面试无关的问题（如政治、色情、暴力）
5. 如果用户问的是第三方库的具体 API 用法，而文档里没有，直接说"这个我没用过"
```

**设计要点**：
- **具体而非抽象**：不说"不要撒谎"，说"文档里写 80% 就不要说 95%"
- **加负例**：告诉 LLM 什么情况下应该说"不知道"
- **重复强化**：在 Prompt 开头和结尾都放约束，增加权重

---

### 第三层：检索阈值过滤

如果检索结果和问题的相似度太低，宁可让 LLM 说"不知道"，也不要塞无关内容。

```typescript
// retriever.ts
const SIMILARITY_THRESHOLD = 0.65;

const topChunks = scored
  .slice(0, topK)
  .filter((item) => item.score >= SIMILARITY_THRESHOLD)  // ← 低于阈值丢弃
  .map((item) => item.chunk);

// 如果过滤后为空，contextText 为空字符串
// System Prompt 里就不会出现"以下是相关项目文档"
// LLM 会基于通用知识回答，但受"不知道就承认"约束
```

**阈值设定依据**：
- 0.65 以下：检索结果和问题语义相关性很低
- 0.65-0.80：有一定相关性，需要 LLM 判断
- 0.80 以上：高相关性，可以直接用

---

### 第四层：输出后校验（可选增强）

生成回答后，用规则检查是否有明显幻觉。

```typescript
// 简单校验：回答中的数字是否都在知识库中出现过
function hallucinationCheck(answer: string, chunks: Chunk[]): boolean {
  // 提取回答中的所有数字
  const numbers = answer.match(/\\d+%?/g) || [];
  
  // 检查这些数字是否出现在知识库中
  const chunkText = chunks.map(c => c.content).join(' ');
  
  for (const num of numbers) {
    if (!chunkText.includes(num)) {
      console.warn(`[幻觉风险] 回答中出现了知识库没有的数字: ${num}`);
      return false;
    }
  }
  
  return true;
}
```

**注意**：这只能做简单校验，复杂语义幻觉需要 LLM-as-a-Judge。

## 四、评测集里的对抗 Case

评测集中专门设计诱导幻觉的问题：

```
对抗 Case 示例：

1. "你在飞猪做过小程序吗？"
   → 期望："文档中没有提到小程序项目"（不要编造）

2. "接送列表的秒开率是 95% 吧？"
   → 期望："文档中提到秒开率是 80%，不是 95%"（纠正错误前提）

3. "你用过 Next.js 的 ISR 吗？"
   → 期望："文档中没有提到 ISR"（不要编造技术细节）

4. "你在阿里待了 5 年？"
   → 期望："文档中没有提到具体年限"（不要编造时间线）

5. "说说你做过的电商项目"
   → 期望："文档中没有电商项目"（不要扩展无关项目）
```

## 五、RAG 为什么能防幻觉

```
┌─────────────────────────────────────────────────────────────┐
│                    传统 LLM 调用                              │
│                                                             │
│   用户提问 ──► LLM 基于训练数据回答                          │
│                    │                                        │
│                    ▼                                        │
│              可能编造（训练数据里没有你的信息）                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
                              vs
┌─────────────────────────────────────────────────────────────┐
│                    RAG + 约束                                 │
│                                                             │
│   用户提问 ──► 检索知识库 ──► 只把检索结果给 LLM              │
│                                    │                        │
│                                    ▼                        │
│                              "只能基于这些回答"               │
│                              "不知道就承认"                   │
│                                    │                        │
│                                    ▼                        │
│                              回答基于真实文档                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**一句话总结**：
> **RAG 防幻觉不是靠 LLM 变诚实了，而是把 LLM 的"素材范围"锁死了。**
>
> LLM 只能从 `[1][2][3]` 这些文档里找答案，文档里没有的就必须说不知道。

## 六、常见追问

### Q: 如果知识库本身有错误怎么办？

**回答**：
> "知识库错误是'输入错误'，不是'幻觉'。解决方法是：
> 1. **源头治理** — 定期 review 知识库文档，确保数据准确
> 2. **版本管理** — 知识库变更留痕，发现错误可以快速回滚
> 3. **用户反馈** — 点踩的反馈会人工复核，发现知识库错误及时修正"

### Q: 如果面试官问的是知识库以外的技术问题呢？

**回答**：
> "System Prompt 里明确约束：'若上下文中没有相关信息，坦诚告知'。比如面试官问'你了解 Rust 吗'，如果知识库里没有，Agent 会回答'文档中没有提到 Rust 相关经验'。
>
> 这是正确的做法——面试中承认不知道比编造答案好一百倍。"

### Q: LLM 会不会无视约束，继续编造？

**回答**：
> "有可能，尤其是模型能力较弱的时候。我们的多层防护就是为了降低这个概率：
> 1. RAG 锁定素材范围（物理限制）
> 2. Prompt 反复强调约束（心理限制）
> 3. 阈值过滤避免塞无关内容（减少干扰）
> 4. 评测集里的对抗 case 持续测试（验证效果）
>
> 没有 100% 的防幻觉方案，但多层防护可以把概率降到很低。"

## 七、面试话术（完整版）

> **"你怎么防止 Agent 幻觉？"**
>
> 我们做了五层防护。
>
> **第一层是知识边界锁定**：通过 RAG 检索，只把知识库中相关的文档 chunks 放进 Prompt。LLM 能看到的素材只有这些，从源头上限制了编造空间。
>
> **第二层是 Prompt 防御性指令**：System Prompt 里明确写了"不知道就承认"、"不要编造文档中没有的数据"、"文档里写 80% 就不要说 95%"。约束写得越具体，LLM 遵守的概率越高。
>
> **第三层是检索阈值过滤**：相似度低于 0.65 的结果直接丢弃，不塞进 Prompt。避免把无关内容给 LLM，减少干扰和误用。
>
> **第四层是输出后校验**：生成回答后，简单检查回答中的数字是否都在知识库中出现过，发现异常打日志告警。
>
> **第五层是用户反馈闭环**：每个回答有点赞/点踩，点踩率高的回答人工复核，持续优化 Prompt 和知识库。
>
> 核心思路是：RAG 防幻觉不是靠 LLM 变诚实，而是把 LLM 的素材范围锁死了。它只能从我们提供的文档里找答案，文档里没有的就必须说不知道。
