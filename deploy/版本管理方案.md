# interview-agent 云端版本管理方案

## 一、设计目标

- **不可变部署**：每次发布创建独立版本目录，历史版本不覆盖、不修改
- **秒级回滚**：通过符号链接/目录切换，1 秒内切到任意历史版本
- **本地可溯**：每个远程版本记录对应的 git 分支与 commit hash
- **自动清理**：保留最近 10 个版本，自动删除更旧的（可配置）

---

## 二、核心架构

### 2.1 轻量服务器（server + knowledge）

采用 **Releases + Current Symlink** 模式：

```
/var/www/interview-agent/
├── releases/                          # 所有历史版本（不可变）
│   ├── 20250708-143022-a1b2c3d/      # 版本目录命名：时间戳-git短哈希
│   │   ├── server/                   # 完整 server（含 dist/ + package.json）
│   │   ├── knowledge/                # 完整 knowledge 目录
│   │   ├── ecosystem.config.js       # 该版本 PM2 配置副本
│   │   └── meta.json                 # 版本元信息（分支、commit、描述）
│   ├── 20250709-101530-b2c3d4e/
│   └── ...
├── current -> releases/20250709-101530-b2c3d4e/   # 符号链接，指向当前版本
└── shared/                            # 共享数据，不随版本变更
    ├── .env                           # 环境变量（敏感信息，单独管理）
    └── data/                          # SQLite 数据库、持久化数据
```

**PM2 配置中 `cwd` 指向 `/var/www/interview-agent/current`**，因此切换 `current` 符号链接即可改变服务运行的代码版本，无需修改 PM2 配置本身。

### 2.2 OSS（client 前端）

OSS 不支持符号链接，采用 **Versions 目录 + Current 覆盖** 模式：

```
app/resume/
├── index.html                         # 当前版本首页
├── assets/                            # 当前版本资源
├── version.json                       # 当前版本元信息
└── versions/                          # 历史版本（不可变）
    ├── 20250708-143022-a1b2c3d/
    │   ├── index.html
    │   └── assets/
    ├── 20250709-101530-b2c3d4e/
    └── ...
```

- **部署**：新版本上传到 `versions/版本号/`，然后复制到根目录覆盖 current
- **回滚**：将指定历史版本从 `versions/` 复制回根目录
- **元信息**：`version.json` 记录当前版本号，便于查询和回滚时确认

## 三、版本标识规范

每个版本使用统一的版本 ID：

```
{YYYYMMDD}-{HHMMSS}-{git-short-hash}
# 例如：20250708-143022-a1b2c3d
```

- **时间戳**：精确到秒，保证唯一性，一眼看出发布时间
- **git short hash**：前 7 位，可追溯到本地具体 commit

每个版本同时附带 `meta.json`（服务器）或 `version.json`（OSS）记录：

```json
{
  "versionId": "20250708-143022-a1b2c3d",
  "gitBranch": "feature/login-fix",
  "gitCommit": "a1b2c3d4e5f6...",
  "deployedAt": "2025-07-08T14:30:22Z",
  "description": "可选：本次发布描述"
}
```

## 四、部署流程

### 4.1 部署 server + knowledge（本地执行）

```bash
cd interview-agent
bash deploy/deploy-server.sh
```

内部流程：
1. 读取本地 git 分支和 commit hash，生成版本 ID
2. 本地 `npm run build` 编译 server
3. 打包：server（dist/ + package.json）+ knowledge + ecosystem.config.js + meta.json
4. `scp` 上传到服务器 `releases/版本号/`
5. **SSH 远程执行**：进入新版本 server 目录，`npm install --production`
6. **SSH 远程执行**：更新 `current` 符号链接指向新版本
7. **SSH 远程执行**：`pm2 reload` 平滑重启服务

### 4.2 部署 client 到 OSS（本地执行）

```bash
cd interview-agent
bash deploy/deploy-oss.sh
```

内部流程：
1. 读取本地 git 信息，生成版本 ID
2. 本地 `npm run build` 编译 client
3. `ossutil cp` 上传构建产物到 `versions/版本号/`
4. `ossutil cp` 复制该版本到根目录覆盖 current
5. 更新根目录 `version.json`
6. 提示刷新 CDN 缓存

### 4.3 一键部署全部

```bash
cd interview-agent
bash deploy/deploy-all.sh
```

顺序执行 `deploy-server.sh` + `deploy-oss.sh`。

## 五、回滚流程

### 5.1 回滚 server（交互式）

```bash
bash deploy/rollback-server.sh
```

脚本会：
1. SSH 到服务器，列出 `releases/` 下所有版本（按时间倒序）
2. 显示每个版本的 meta.json（分支、commit、时间）
3. 输入要回滚的版本号
4. SSH 修改 `current` 符号链接
5. `pm2 reload` 平滑重启
6. 服务在 1 秒内完成回滚，零停机

### 5.2 回滚 OSS（交互式）

```bash
bash deploy/rollback-oss.sh
```

脚本会：
1. 通过 `ossutil ls` 列出所有历史版本
2. 输入要回滚的版本号
3. `ossutil cp` 将该版本从 `versions/` 复制到根目录
4. 更新 `version.json`
5. 提示去 CDN 控制台刷新缓存（或调用 API 刷新）

### 5.3 紧急回滚（指定版本号，非交互）

```bash
# server
bash deploy/rollback-server.sh 20250708-143022-a1b2c3d

# OSS
bash deploy/rollback-oss.sh 20250708-143022-a1b2c3d
```

## 六、版本清理策略

服务器磁盘有限，自动保留最近 **10 个版本**（可配置），更旧的自动删除。

**手动清理**（在服务器执行）：

```bash
ssh root@your-server "bash /var/www/interview-agent/scripts/clean-releases.sh"
```

或在本地：

```bash
bash deploy/clean-releases.sh
```

**自动清理**：可在服务器上添加 crontab，每天凌晨执行一次：

```cron
0 3 * * * bash /var/www/interview-agent/scripts/clean-releases.sh >> /var/log/clean-releases.log 2>&1
```

OSS 存储成本较低，历史版本可保留更久。如需清理，在阿里云 OSS 控制台手动删除旧版本目录，或同样用脚本定期清理。

## 七、首次初始化（服务器端）

在新服务器或首次启用版本管理时，执行一次：

```bash
ssh root@your-server

# 创建目录结构
mkdir -p /var/www/interview-agent/releases
mkdir -p /var/www/interview-agent/shared/data
ln -s /var/www/interview-agent/releases/placeholder /var/www/interview-agent/current

# 准备环境变量（从备份或手动创建）
touch /var/www/interview-agent/shared/.env

# 准备数据库目录
mkdir -p /data/interview-agent/backup
```

然后正常执行部署脚本即可。

## 八、配置项汇总

修改以下脚本顶部的配置变量：

| 脚本 | 配置项 | 说明 |
|-----|-------|-----|
| `deploy-server.sh` | `SERVER_HOST` | 轻量服务器 IP |
| `deploy-server.sh` | `SERVER_USER` | SSH 用户名 |
| `deploy-server.sh` | `APP_DIR` | 服务器部署根目录 |
| `deploy-oss.sh` | `OSS_BUCKET` | OSS Bucket 名称 |
| `deploy-oss.sh` | `OSS_ENDPOINT` | OSS 地域端点 |
| `deploy-oss.sh` | `OSS_PREFIX` | OSS 中的路径前缀 |
| `rollback-server.sh` | 同上 | 与 deploy-server 一致 |
| `rollback-oss.sh` | 同上 | 与 deploy-oss 一致 |

**依赖工具**：
- `ossutil`（阿里云 OSS 命令行工具）
- `ssh` / `scp`（系统自带）
- 服务器上已安装 `node`、`npm`、`pm2`

## 九、与本地 Git 分支的协作

| 场景 | 本地操作 | 云端操作 |
|-----|---------|---------|
| 日常开发 | 在 feature 分支开发 | 无 |
| 预发布测试 | 合并到 `release/*` 分支，执行部署 | 部署到云端，生成新版本 |
| 生产发布 | 合并到 `main` 分支，打 tag | 部署到云端 |
| 发现线上 bug | 无需改代码 | 执行 rollback 脚本秒级回滚 |
| bug 修复后 | 在分支修复，验证后重新部署 | 部署新版本 |
| 版本追溯 | `git log` 找到 commit | 对比 meta.json 中的 gitCommit |

## 十、回滚速度对比

| 方式 | 耗时 | 是否停机 | 数据影响 |
|-----|------|---------|---------|
| 传统备份恢复 | 5~30 分钟 | 是 | 可能丢失期间数据 |
| 本方案（server） | **< 1 秒** | 否（PM2 reload） | 无，数据库在 shared |
| 本方案（OSS） | **< 10 秒** | 否（CDN 回源） | 无 |
