# 变更提案：面试官访问控制

## 背景

当前 interview-agent 的聊天入口直接暴露在简历页面上，任何访问者都可以点击并与我进行对话。由于简历入口可能被很多人看到，存在以下风险：

- 非招聘方误用或滥用对话功能。
- 无法区分真正的面试官与普通浏览者。
- 对话记录中混入无效访谈，影响后续回顾。

## 目标

为聊天入口增加一层访问控制，用户输入**公司名称**后即可进入对话，同时后端记录公司名用于审计。

## 范围

### included（范围内）

1. 公司名称输入式认证。
2. 访问会话（session token）管理。
3. 访问审计日志（公司名称、时间、IP、UA）。
4. 前端认证弹窗 `AuthGate`。
5. 后端认证接口 `/api/access/*`。
6. 显式的访问控制开关 `ACCESS_CONTROL_ENABLED`。

### excluded（范围外）

1. 企业邮箱验证码流程（已替换为公司名方式）。
2. 邮箱域名白名单机制（保留实现但本次不启用）。
3. 复杂的企业 OAuth/SSO 集成。
4. 人工审核流程。
5. 多设备同步认证状态。

## 验收标准

- [ ] 未输入公司名称无法进入对话。
- [ ] 输入公司名称后调用后端接口生成 session token，刷新页面无需重复验证。
- [ ] 未认证用户点击聊天入口时显示认证弹窗，无法进入对话。
- [ ] 后端所有聊天相关接口（除健康检查）需携带有效 session token。
- [ ] 配置 `ACCESS_CONTROL_ENABLED=false` 时访问控制关闭，保持公开访问。

## 风险与假设

- **风险**：公司名称可被随意填写，无法严格证明身份。后续如需更强制认证，可切换回邮箱验证码或 OAuth。
- **假设**：面试官愿意输入所在公司名称完成一次简单认证。
