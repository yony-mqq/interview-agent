# Harness 研发范式面试问答

> 适用场景：面试官问到 AI 辅助研发、Claude Code Harness、Spec-Driven Development 等相关话题时使用。

---

## 一、概念理解

### Q1：什么是 Harness 研发范式？

**A**：Harness 是让 AI 编码助手（如 Claude Code、Copilot、Cursor 等）能够稳定、安全、高效协作的一套「工程化基础设施 + 研发流程规范」。

核心目标：让 AI 从「辅助工具」变成「可信赖的协作者」。

---

### Q2：Harness 和传统研发流程有什么区别？

| 维度 | 传统研发 | Harness 范式 |
|---|---|---|
| 需求承接 | PRD / 口头沟通 | 结构化 Spec / OpenSpec |
| 代码生成 | 人工编写 | AI 生成 + 人工 Review |
| 验证方式 | 人工测试 | 自动化测试 + Harness 检查 |
| 知识沉淀 | 文档 / Wiki | CLAUDE.md / .claude/ / Skills / MCP |
| 安全边界 | Code Review | 权限 + Hooks + MCP 沙箱 |

---

## 二、成熟度等级

### Q3：Harness 成熟度通常分几级？你们团队在哪一级？

常见四级：

| 等级 | 特征 | 关键问题 |
|---|---|---|
| **初级** | 零散使用 AI，靠 prompt 试探 | AI 输出不稳定，上下文易丢失 |
| **SDD** | 有 OpenSpec / 设计文档驱动开发 | 需求→设计→实现→验收可追踪 |
| **TDD + SDD** | 设计文档 + 测试先行 | AI 在测试约束下生成代码，质量可控 |
| **高级** | 自研 Skills、MCP、Hooks，AI 深度集成工作流 | 形成组织级 AI 研发资产 |

**答题建议**：结合自己项目实际，明确说出当前等级和升级路径。

---

### Q4：怎么判断一个项目是否适合接入 Harness？

- 代码是否「AI 可读」：有清晰的 README、类型、模块化结构
- 是否有可复用的研发规范：命名、测试、目录结构
- 是否有明确的验收标准：测试用例、Lint 规则、性能基线
- 安全边界是否清晰：权限、敏感数据、部署流程

---

## 三、工程实践

### Q5：Harness 里 CLAUDE.md / .claude/ / Skills / MCP 分别起什么作用？

| 组件 | 作用 |
|---|---|
| **CLAUDE.md** | 项目级「AI 使用说明书」：项目背景、技术栈、规范、常用命令 |
| **.claude/** | 项目级 AI 配置目录：hooks、settings、rules、commands |
| **Skills** | 可复用领域能力包，如「飞猪告警查询」「Kami 排版」「GitLab MR」 |
| **MCP** | 外部工具接入协议，让 AI 调用浏览器、数据库、API、文件系统等 |
| **Hooks** | 在 AI 动作前后插入检查/拦截，如提交前跑 lint、禁止 rm -rf |

---

### Q6：你们怎么保证 AI 生成代码的质量？

- **Spec 先行**：OpenSpec 明确输入输出、边界条件、验收标准
- **测试约束**：TDD，先写测试再让 AI 实现
- **自动化检查**：Lint、Type Check、Unit Test、Harness 检查
- **人工 Review**：核心逻辑/安全相关代码必须人工确认
- **小步迭代**：复杂任务拆小，每一步可验证

---

### Q7：遇到过 AI 「幻觉」或越权操作吗？怎么防？

- 权限最小化：AI 只有读代码、跑测试、提交 MR 权限，无生产部署权限
- MCP 沙箱：浏览器/文件/命令类 MCP 限制在工作区
- Hooks 拦截：危险命令（rm、git push --force、wget 不明文件）自动阻断
- 审计日志：记录 AI 操作，便于复盘

---

## 四、价值与落地

### Q8：引入 Harness 后，研发效率/质量有什么变化？

可从以下指标回答：

- **需求交付周期**：简单任务从 X 小时降到 Y 分钟
- **重复代码减少**：通过 Skills/MCP 统一工具调用
- **Bug 率**：AI 导致的回归问题占比、拦截率
- **新人上手成本**：靠 CLAUDE.md + Skills 降低领域知识门槛
- **知识沉淀**：设计文档、规范从「人脑」转移到「项目资产」

---

### Q9：推广 Harness 时最大的阻力是什么？怎么解决？

| 阻力 | 解法 |
|---|---|
| 同事不信任 AI | 从低风险任务切入，展示可验证的成果 |
| 规范落地难 | 把规范写进 CLAUDE.md / Hooks，让 AI 自动约束 |
| 安全顾虑 | 权限分级 + 审计 + 人工 Review 兜底 |
| 上下文碎片化 | 用 OpenSpec + Memory 做长期知识沉淀 |

---

## 五、一句话总结

### Q10：用一句话总结 Harness 研发范式的核心？

> **以 Spec 为驱动、以测试为约束、以 AI 为执行者、以 Harness 基础设施为安全边界，实现可预测、可验证、可持续的 AI 协作研发。**
